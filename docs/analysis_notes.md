# 电商用户行为分析记录

## 1. 行为类型分布

本项目首先统计了用户行为日志中 view、cart、fav、buy 四类行为的次数和占比。

从结果来看，view 行为占比最高，buy 行为占比最低。这符合电商平台的常见用户行为特征：大部分用户会产生浏览行为，但只有少部分浏览最终会转化为购买。

该结果说明，平台用户行为存在明显的转化漏斗：

浏览 view -> 收藏 fav / 加购 cart -> 购买 buy

后续分析可以继续关注以下问题：

1. 哪些商品浏览量高但购买量低？
2. 哪些类目的购买转化率更高？
3. 哪些用户更容易从浏览转化为购买？
4. 是否可以根据用户历史行为预测购买概率？

## 2. 商品购买转化率分析

本项目进一步统计了每个商品的浏览次数和购买次数，并计算商品购买转化率：

商品购买转化率 = 购买次数 / 浏览次数

为了避免低样本商品造成误导，分析时仅保留浏览次数不少于 10 次的商品。

从业务角度看，转化率较高的商品说明用户浏览后更容易产生购买行为，可能具备较好的价格、评价、商品吸引力或推荐匹配度。转化率较低但浏览量较高的商品，则可能存在详情页吸引力不足、价格不合适、用户匹配不准确等问题。

后续可以进一步分析：
1. 不同商品类目的转化率是否存在明显差异；
2. 高浏览低转化商品是否集中在某些类目；
3. 是否可以根据用户历史行为预测其购买概率；
4. 是否可以基于用户相似行为构建推荐系统。

## 3. 类目购买转化率分析

在商品转化率分析的基础上，本项目进一步从商品类目维度统计浏览次数、购买次数和购买转化率。

类目购买转化率 = 类目购买次数 / 类目浏览次数

相比单个商品，类目维度的统计结果更稳定，更适合观察不同品类之间的整体购买倾向。

如果某些类目转化率较高，说明该类目下的商品更容易促成购买，后续可以在推荐、活动资源、商品运营中给予更多关注。如果某些类目浏览量高但转化率低，则可能需要进一步分析价格、商品质量、用户匹配度或详情页表现。

后续可以继续分析：
1. 高转化类目中是否存在明星商品；
2. 低转化类目是否存在高浏览低购买的问题；
3. 不同用户是否偏好不同类目；
4. 类目偏好是否可以作为购买预测模型的特征。

## 4. 用户活跃度分析

本项目从用户维度统计了每个用户的浏览、收藏、加购、购买次数，并计算用户活跃天数和总行为次数。

根据用户总行为次数，将用户划分为低活跃、中活跃和高活跃三类。用户分层可以帮助我们观察不同活跃程度用户的行为差异，也可以作为后续购买预测模型的重要特征。

从业务角度看，高活跃用户通常具有更强的购买潜力，后续可以进一步分析这类用户的类目偏好、购买转化路径和推荐响应情况。低活跃用户则可能需要通过更精准的推荐、优惠或召回策略提升活跃度。

后续可以继续分析：
1. 不同活跃等级用户的购买率是否不同；
2. 高活跃用户偏好哪些商品或类目；
3. 用户活跃等级是否能提升购买预测模型效果；
4. 是否可以基于用户行为特征构建用户画像。

## 5. 购买预测模型 baseline

本项目将用户-商品维度的行为数据构造成机器学习样本，用于预测用户是否会购买某个商品。

第一版模型使用逻辑回归作为 baseline，输入特征包括用户对商品的浏览次数、收藏次数和加购次数，预测目标为用户是否购买该商品。

模型评估结果如下：

| 指标      | 数值   |
| --------- | ------ |
| Accuracy  | 0.9945 |
| Precision | 1.0000 |
| Recall    | 0.9167 |
| F1        | 0.9565 |

从结果看，模型在模拟数据上表现较好，能够较准确识别潜在购买行为。但由于当前数据为模拟生成，且特征与标签之间关系较简单，因此该结果不能直接代表真实业务场景下的效果。

后续需要进一步优化：
1. 使用真实公开数据集重新构建样本；
2. 按时间窗口构建训练集和测试集，避免数据泄漏；
3. 增加用户活跃度、商品热度、类目偏好等特征；
4. 尝试随机森林、LightGBM 等模型并进行对比。

## 6. 热门商品推荐 baseline

本项目实现了一个基于商品热度的推荐 baseline。该方法不考虑用户个性化差异，而是根据全站用户行为计算商品热度分数，并向用户推荐热度最高的商品。

商品热度分数定义为：

商品热度分数 = 1 × 浏览次数 + 2 × 收藏次数 + 3 × 加购次数 + 5 × 购买次数

其中，购买行为权重最高，表示其更能反映用户对商品的真实兴趣；浏览行为权重最低，因为浏览只能代表较弱兴趣。

热门推荐方法的优点是简单、稳定、容易解释，适合冷启动或作为推荐系统 baseline。缺点是缺少个性化，所有用户看到的推荐结果相同，无法根据不同用户的兴趣偏好进行差异化推荐。

后续可以继续实现基于物品相似度的协同过滤推荐，使推荐结果更加个性化。

## 7. 基于物品协同过滤的个性化推荐

在热门商品推荐 baseline 的基础上，本项目进一步实现了基于物品相似度的协同过滤推荐，即 Item-Based Collaborative Filtering。

该方法的核心假设是：如果两个商品经常被同一批用户交互，那么这两个商品可能具有相似性。对于某个目标用户，可以根据其历史交互过的商品，找到相似商品作为候选推荐，并过滤掉用户已经交互过的商品。

本项目首先将用户行为转换为兴趣权重：

- 浏览 view：1
- 收藏 fav：2
- 加购 cart：3
- 购买 buy：5

然后统计用户交互过的商品集合，计算商品之间的共现次数，并使用类似余弦相似度的公式计算商品相似度：

商品相似度 = 两商品共同出现次数 / sqrt(商品A出现次数 × 商品B出现次数)

在生成推荐时，对目标用户历史交互过的商品，寻找其相似商品，并将相似度累加为推荐分数，最终输出 TopN 推荐结果。

相比热门推荐，ItemCF 可以根据用户历史行为生成个性化推荐结果。但当前版本仍然比较基础，后续可以继续优化：
1. 推荐时引入用户对历史商品的兴趣分数，而不仅仅累加相似度；
2. 为多个用户批量生成推荐结果；
3. 对推荐效果进行离线评估，例如 Precision@K、Recall@K；
4. 与热门推荐 baseline 进行效果对比。

### 多用户批量推荐

在第一版 ItemCF 中，系统仅为单个目标用户生成推荐结果。后续将推荐逻辑扩展为批量生成推荐结果，选择前 20 个用户作为目标用户，并分别为每个用户生成 Top 10 个性化推荐商品。

批量推荐结果保存为：

data/processed/item_cf_recommendations.csv

该文件包含以下字段：

| 字段            | 含义        |
| --------------- | ----------- |
| user_id         | 目标用户 ID |
| item_id         | 推荐商品 ID |
| recommend_score | 推荐分数    |

通过批量生成推荐结果，可以更方便地观察不同用户的推荐差异，也为后续推荐效果评估打下基础。
